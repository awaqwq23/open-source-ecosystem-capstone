# 校园页子应用架构迁移指南

本文说明校园页新架构下的文件安排方式，以及仍在旧架构路径上开发的代码如何迁移。

## 新架构文件安排

校园页是聚合型页面，主入口和具体子应用分开：

- `lib/features/pages/campus/presentation/pages/campus_page.dart`：校园页九宫格和入口聚合页。
- `lib/features/pages/campus/sub_apps/`：校园页下的实际子应用目录。
- `lib/features/pages/campus/README.md`：校园页目录规则说明。

`sub_apps/` 的一级目录必须严格对应一个实际子应用。辅助流程不要单独成为一级子应用目录，而是放进所属子应用内部。

当前子应用安排如下：

- `sub_apps/timetable/`：课程表子应用。
- `sub_apps/score/`：成绩子应用，包括成绩页面、成绩模型和成绩服务。
- `sub_apps/seat_reservation/`：自习预约子应用，包括 WebView 页面和授权服务。
- `sub_apps/luojia_ecard/`：珞珈 E 卡与 E 卡付款码子应用。

每个子应用内部继续按 MVVM 分层：

- `presentation/`：页面、组件、ViewModel。
- `domain/`：业务模型、用例、仓储接口。
- `data/`：服务、适配器、数据源、仓储实现。

不要为了占位创建空目录。某个子应用暂时只有页面时，只保留 `presentation/` 即可。

## 共享能力放置规则

以下能力不属于某个校园子应用，不要移动进 `campus/sub_apps/`：

- `lib/features/whu_auth/`：武大统一认证，多个校园子应用复用。
- `lib/features/luotopia_auth/`：Luotopia 账号能力。
- `lib/features/components/wallpaper/`：跨页面壁纸能力。
- `lib/shared/presentation/widgets/app_web_view_page.dart`：通用 WebView 页面框架。
- `lib/shared/domain/` 和 `lib/shared/data/` 下的日程、课程表共享实体与仓储。

校园子应用可以依赖这些共享能力，但不要反向让共享能力依赖具体子应用。

## 开发中分支迁移步骤

如果你的分支仍基于旧架构开发，按下面顺序迁移：

1. 先确认代码属于哪个实际校园子应用。
2. 将新增文件移动到对应 `sub_apps/<子应用>/` 目录。
3. 如果代码是课程导入相关，移动到 `sub_apps/timetable/course_import/`，不要放到 `sub_apps/course_import/`。
4. 更新所有 import，避免继续引用旧路径。
5. 确认路由路径字符串不变，只修改页面类的 import。
6. 对照 `lib/features/pages/campus/README.md` 检查目录边界。

迁移后建议搜索旧路径：

```powershell
rg "features/components/course_import|sub_apps/course_import|features/pages/campus/data|features/pages/campus/domain/models/score_entity|features/pages/campus/presentation/pages/(score_page|seat_reservation_page|luojia_ecard_webview_page|campus_timetable_page)" lib test
```

没有输出表示旧路径引用已经清理干净。

## 新增校园子应用规则

新增校园子应用时，先在 `sub_apps/` 下建立一个以实际子应用命名的目录，例如：

```text
lib/features/pages/campus/sub_apps/library/
lib/features/pages/campus/sub_apps/venue/
lib/features/pages/campus/sub_apps/classroom/
```

如果只是某个子应用的内部流程，不要建立 `sub_apps/` 一级目录。例如课程导入属于课程表，所以放在 `sub_apps/timetable/course_import/`。

新增入口时，只在 `app/router/app_router.dart` 和 `app/router/app_route_paths.dart` 注册路由；页面实现仍放在对应子应用目录。
