# 武汉大学教务课程字段推测

本文只依据 `docs/全校课表开发/表结构.md` 中给出的 HTML 表格内容推测，不引用当前应用代码里的“课程”概念。

## 结论

这份表格里的一行更像“某学期某课程的一个教学班/开课班级”，而不是抽象的课程目录项。

例如 `算法设计与分析` 拥有相同的 `课程号` 和 `课程名称`，但出现多个 `教学班`、授课老师、上课人数和时间地点。因此，若要建立统一实体，至少应区分：

- 课程目录：跨学期相对稳定的课程定义，例如课程号、课程名称、学分。
- 开课教学班：某学年学期里具体开出的班，例如教学班、老师、人数、面向年级专业、时间地点。
- 排课安排：一个教学班在星期几、哪些周、哪些节、哪个教室上课。
- 教材信息：教材名称、出版社，可能随教学班或课程变化。

## 原始表头字段

表格出现的字段如下：

| 原字段 | 推测含义 | 建议类型 | 备注 |
| --- | --- | --- | --- |
| 学年 | 学年 | string | 样例为 `2025-2026`。 |
| 学期 | 学期 | string / int | 样例为 `2`，不要过早假设只有数字。 |
| 教学班 | 教学班唯一标识或展示名 | string | 样例包含学年、学期、课程号、专业/班号等信息，应优先作为教学班级别标识。 |
| 课程号 | 课程编号 | string | 样例为长数字串，不能用数值类型，避免前导零或格式变化问题。 |
| 课程名称 | 课程名称 | string | 如 `软件工程`、`算法设计与分析`。 |
| 开课学院 | 实际开课学院 | string | 样例为 `计算机学院`。 |
| 计划学院 | 培养方案所属学院 | string | 样例同为 `计算机学院`，但字段语义不同于开课学院。 |
| 学分 | 学分 | decimal | 样例为 `3.5`、`4.0`。 |
| 课程性质 | 课程性质 | string | 如 `专业教育必修`。 |
| 课程类别名称 | 课程类别 | string | 如 `核心课程`、`专业课程`、`大类平台`。 |
| 开课类型 | 开课类型 | string | 如 `专业教育课程`。 |
| 年级 | 面向年级 | string / int | 样例为 `2024`。建议先按字符串保存。 |
| 专业 | 面向专业 | string | 样例为 `软件工程`。 |
| 成绩录入老师 | 主负责老师/成绩录入老师 | string | 不一定等同于全部任课教师。 |
| 职称 | 成绩录入老师职称 | string | 如 `副教授`、`教授`、`讲师`。 |
| 上课人数 | 容量/已选人数或计划/实际人数 | string + parsed numbers | 样例为 `80\74`、`90\88`。只能推测是两个数量，具体含义不能仅凭表格确认。 |
| 理论 | 理论学时 | int? | 样例为 `48`。 |
| 上机 | 上机学时 | int? | 样例为空。 |
| 实验 | 实验学时 | int? | 样例为 `12`、`24`。 |
| 实践 | 实践学时 | int? | 样例为空。 |
| 周日 | 周日排课 | string | 可为空。 |
| 周一 | 周一排课 | string | 可为空，内容为周次、节次、地点组合。 |
| 周二 | 周二排课 | string | 同上。 |
| 周三 | 周三排课 | string | 同上。 |
| 周四 | 周四排课 | string | 同上。 |
| 周五 | 周五排课 | string | 同上。 |
| 周六 | 周六排课 | string | 同上。 |
| 选课备注 | 选课备注 | string | 样例多为空。 |
| 其他教师 | 其他教师 | string | 样例多为空。 |
| 教材名称 | 教材名称 | string | 如 `软件工程`、`算法设计技巧与分析（修订版）`。 |
| 出版社 | 出版社 | string | 如 `清华大学出版社`、`电子工业出版社`。原值可能有多余空格。 |

## 建议实体拆分

### 1. 课程目录 CourseCatalog

适合承载相对稳定、可跨教学班复用的信息。

| 建议字段 | 来源字段 | 说明 |
| --- | --- | --- |
| course_code | 课程号 | 课程编号，字符串。 |
| course_name | 课程名称 | 课程名称。 |
| credits | 学分 | 学分。 |
| course_nature | 课程性质 | 如专业教育必修。 |
| category_name | 课程类别名称 | 如核心课程、专业课程。 |
| offering_type | 开课类型 | 如专业教育课程。 |

注意：`课程性质`、`课程类别名称`、`开课类型` 也可能随培养方案或开课记录变化。仅凭表格不能确认它们是否属于课程目录的稳定属性。

### 2. 开课教学班 CourseOffering

这是表格每一行最直接对应的实体。

| 建议字段 | 来源字段 | 说明 |
| --- | --- | --- |
| academic_year | 学年 | 如 `2025-2026`。 |
| semester | 学期 | 如 `2`。 |
| teaching_class_id | 教学班 | 建议作为业务唯一标识候选。 |
| course_code | 课程号 | 关联课程目录。 |
| course_name_snapshot | 课程名称 | 保留快照，避免课程目录后续改名影响历史记录。 |
| offering_college | 开课学院 | 实际开课单位。 |
| plan_college | 计划学院 | 培养方案或计划归属单位。 |
| grade | 年级 | 面向年级。 |
| major | 专业 | 面向专业。 |
| primary_teacher_name | 成绩录入老师 | 更准确地说是成绩录入老师，不能直接等同全部任课老师。 |
| primary_teacher_title | 职称 | 成绩录入老师职称。 |
| other_teachers_raw | 其他教师 | 原始其他教师文本。 |
| student_count_raw | 上课人数 | 原始人数文本。 |
| student_count_first | 上课人数解析值 1 | 从 `80\74` 的前半段解析。具体语义待确认。 |
| student_count_second | 上课人数解析值 2 | 从 `80\74` 的后半段解析。具体语义待确认。 |
| selection_remark | 选课备注 | 选课备注。 |

候选唯一键：

- 首选：`教学班`。
- 保守组合：`学年 + 学期 + 教学班`。
- 不建议只用：`课程号 + 学年 + 学期`，因为同一课程号在同一学期会有多个教学班。

### 3. 学时结构 CourseHours

可以作为开课教学班的一组字段，也可以拆为子对象。

| 建议字段 | 来源字段 | 说明 |
| --- | --- | --- |
| theory_hours | 理论 | 理论学时。 |
| computer_hours | 上机 | 上机学时。 |
| experiment_hours | 实验 | 实验学时。 |
| practice_hours | 实践 | 实践学时。 |

空值应表示“教务表格未给出”，不要直接等同于 0；导入时可以在业务层再决定是否归零。

### 4. 排课安排 CourseScheduleSlot

周日到周六字段是按星期拆开的原始排课文本。一个单元格内可能有多个排课片段，用逗号分隔；片段里可包含周次、单双周、节次、校区/楼栋/教室、容量和设备。

建议先保留原文，再尽量解析为结构化字段：

| 建议字段 | 来源 | 说明 |
| --- | --- | --- |
| weekday | 字段名 `周日` 到 `周六` | 建议使用 0-6 或 1-7，但需统一约定。 |
| raw_text | 对应星期单元格 | 原始排课字符串。 |
| week_text | 排课字符串 | 如 `1-16周`、`10-16周(双)`。 |
| start_week | 排课字符串解析 | 可解析时保存。 |
| end_week | 排课字符串解析 | 可解析时保存。 |
| week_parity | 排课字符串解析 | `单`、`双` 或空。 |
| section_start | 排课字符串解析 | 如 `6-8节` 的 6。 |
| section_end | 排课字符串解析 | 如 `6-8节` 的 8。 |
| campus_area | 排课字符串解析 | 如 `3区`、`1区`。 |
| building_room | 排课字符串解析 | 如 `2-104`、`计-203`。 |
| room_capacity | 括号内数字 | 如 `(91,多媒体)` 中的 `91`。 |
| room_features | 括号内文本 | 如 `多媒体`。 |

需要注意的格式变体：

- 有的片段显式写 `周一`、`周四`，有的只在列名中体现星期。
- 有的地点前有空格，如 ` 1区计-203`。
- 有的字符串含空地点占位，如 `(,)`。
- 同一星期可能存在不同周次、不同节次或不同教室。
- 教务表格列名已经给出星期，因此解析时不应完全依赖单元格内是否出现 `周一` 这类文本。

### 5. 教材 CourseTextbook

| 建议字段 | 来源字段 | 说明 |
| --- | --- | --- |
| textbook_name | 教材名称 | 教材名称。 |
| publisher | 出版社 | 出版社，需 trim。 |

从样例看，同一课程的教材名称可能有细微版本差异，因此教材更适合挂在开课教学班或教学班快照上，而不是强行作为课程目录唯一属性。

## 建议保留的原始字段

为了避免过早解析导致信息丢失，建议保留：

- `teaching_class_raw`
- `student_count_raw`
- `schedule_sunday_raw` 到 `schedule_saturday_raw`
- `other_teachers_raw`
- `selection_remark_raw`
- `textbook_name_raw`
- `publisher_raw`

## 不能仅凭表格确认的事项

- `上课人数` 中两个数字的确切含义。它很可能是容量/已选、计划/实际或上限/当前人数，但表格本身没有说明。
- `教学班` 是否在全校、跨学年学期绝对唯一。保守起见应和 `学年 + 学期` 一起作为唯一键。
- `成绩录入老师` 是否一定是主讲教师。字段名只说明其负责成绩录入。
- `其他教师` 的分隔规则。样例为空，无法确认多人格式。
- `周日` 到 `周六` 的排课文本是否覆盖所有教学活动，还是只覆盖该表导出的可见课表范围。
- `计划学院` 与 `开课学院` 的精确定义。只能按字面区分为计划归属与实际开课单位。

## 最小统一字段建议

如果先做一版稳定导入模型，建议至少保存这些字段：

## 课程聚类层级推测

只看这份表，武汉大学教务系统里的“课程”更像按开课记录组织，而不是单纯按课程目录组织。表里的字段可以支持一个 5 级课程聚类；如果把具体课表片段也算进教学实体，则可以扩展为 6 级。

### 推荐理解：5 级课程聚类

| 层级 | 名称 | 依据字段 | 说明 |
| --- | --- | --- | --- |
| 1 | 学期批次 | 学年、学期 | 课程首先落在某个教学周期里，例如 `2025-2026` 第 `2` 学期。 |
| 2 | 培养/开课归属 | 开课学院、计划学院、年级、专业 | 表格同时给出开课单位和培养计划对象，说明课程可按学院、年级、专业聚类。 |
| 3 | 课程分类 | 开课类型、课程性质、课程类别名称 | 这是课程在培养方案中的分类维度，例如专业教育课程、专业教育必修、核心课程。 |
| 4 | 课程目录项 | 课程号、课程名称、学分 | 同一个课程号可出现多个教学班，因此它是教学班之上的课程定义层。 |
| 5 | 开课教学班 | 教学班、成绩录入老师、职称、上课人数、其他教师、教材名称、出版社 | 表格每一行最直接对应这个层级。同一课程目录项可拆出多个教学班。 |

按这个理解，适合用于“统一课程实体”的主树是：

```text
学年学期
└── 培养/开课归属
    └── 课程分类
        └── 课程目录项
            └── 开课教学班
```

### 扩展理解：6 级教学实体

如果目标不只是聚类课程，还要表达“这门课具体何时何地上”，则需要在教学班下面再加一级：

| 层级 | 名称 | 依据字段 | 说明 |
| --- | --- | --- | --- |
| 6 | 排课片段 | 周日到周六 | 一个教学班可对应多个周次、节次、教室组合。 |

扩展后的树是：

```text
学年学期
└── 培养/开课归属
    └── 课程分类
        └── 课程目录项
            └── 开课教学班
                └── 排课片段
```

### 关于第 2 级和第 3 级的顺序

`开课学院`、`计划学院`、`年级`、`专业` 与 `课程性质`、`课程类别名称`、`开课类型` 都是聚类维度，但表格本身没有给出教务系统后台的真实树形顺序。

当前推荐把归属信息放在课程分类之前，原因是样例里所有记录都属于 `计算机学院 / 2024 / 软件工程`，而课程分类在这个培养对象下继续分出 `核心课程`、`专业课程`、`大类平台` 等类别。也就是说，从这份表的观察角度看，更像：

```text
某学期的软件工程专业培养计划
└── 专业教育必修 / 核心课程 / 专业教育课程
    └── 软件工程
```

而不是：

```text
某学期的核心课程
└── 软件工程专业
    └── 软件工程
```

不过这只是基于样例值的建模选择，不能证明教务系统真实后台一定这样组织。

### 哪些层级不应混为一谈

- `课程号 + 课程名称` 不能代表一个具体上课班，因为同一课程会有多个 `教学班`。
- `教学班` 不能代表抽象课程，因为它包含学年学期、班号、教师、人数和课表等开课实例信息。
- `周日` 到 `周六` 不是课程分类字段，而是教学班下的排课明细。
- `教材名称` 更像教学班或开课快照属性，不适合直接作为课程目录聚类依据。

因此，若问“课程聚类总共分几级”，最稳妥的回答是：

- 课程聚类本身：5 级。
- 加上具体课表安排：6 级。
